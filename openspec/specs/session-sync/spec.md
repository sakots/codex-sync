# session-sync Specification

## Purpose
複数マシンにあるCodexのセッションファイルを、利用者が用意したGitリポジトリを経由して共有する。既存スクリプトの同期範囲、処理順序、OSごとの上書き動作と失敗時の境界を明確にする。

## Requirements

### Requirement: 同期対象とリポジトリの前提

スクリプトは`~/dev/codex-history`を同期用リポジトリ、`~/.codex/sessions`をローカル保存先として扱い、リポジトリの`sessions/`とのみファイルを同期しなければならない（MUST）。`.git`が存在しない場合は非ゼロで終了しなければならない（MUST）。有効なリポジトリでは両方のsessionsディレクトリを必要に応じて作成しなければならない（MUST）。

#### Scenario: 同期用リポジトリがない

- **WHEN** 利用者のホームに同期用リポジトリの`.git`が存在しない
- **THEN** 非ゼロで終了し、ローカルのsessionsディレクトリを作成しない

#### Scenario: 初回取り込み

- **WHEN** 有効な同期用リポジトリがあり、ローカルのsessionsディレクトリが存在しない
- **THEN** ディレクトリを作成して同期を進める

### Requirement: リモートを先に取り込む

スクリプトはファイルコピーの前に`git pull --rebase`を実行し、失敗時はファイルコピー・コミット・pushを行わず非ゼロで終了しなければならない（MUST）。成功時はリポジトリからローカル、次にローカルからリポジトリの順で再帰的にコピーしなければならない（MUST）。

#### Scenario: 別マシンのセッションを取り込む

- **WHEN** リモートに新しいセッションがあり、ローカルにも別の新しいセッションがある
- **THEN** 両方のセッションがローカルと同期用リポジトリに存在する

#### Scenario: pullが失敗する

- **WHEN** リモートに接続できずpullが失敗する
- **THEN** 非ゼロで終了し、ローカルと同期用リポジトリ間のファイルコピーを行わない

### Requirement: OSごとの上書きと削除の扱い

Ubuntuはコピー元を優先する通常の`rsync -a`、Windowsはコピー先より古いファイルを除外する`robocopy /E /XO`と同等の挙動を維持しなければならない（MUST）。両OSとも片側に存在しないことだけを理由に他方のファイルを削除してはならない（MUST NOT）。同一ファイルへの変更を意味的にマージする契約はない。

#### Scenario: Ubuntuに新しい同名ファイルがある

- **WHEN** リポジトリの同名ファイルがローカルより古く、内容とサイズが異なる
- **THEN** 先の取り込みでリポジトリ側の内容がローカルを上書きする

#### Scenario: Windowsに新しい同名ファイルがある

- **WHEN** リポジトリの同名ファイルがローカルより古く、内容とサイズが異なる
- **THEN** 取り込みではローカルを保持し、書き出しでローカルの内容がリポジトリにコピーされる

#### Scenario: 片側にしかないファイル

- **WHEN** ローカルとリポジトリにそれぞれ別名のファイルがある
- **THEN** 同期後は両方に両ファイルが存在する

### Requirement: 差分のコミットと公開

スクリプトは`sessions/`をステージし、ステージ済み差分があればコミットしてpushしなければならない（MUST）。差分がなければ新しいコミットもpushも行ってはならない（MUST NOT）。この契約の前提として、実行前の同期用リポジトリに利用者が別のステージ済み変更を残さないものとする。

#### Scenario: ローカルの新しいセッションを公開する

- **WHEN** ローカルにのみ存在するセッションを同期する
- **THEN** セッションがリモートの新しいコミットに含まれ、別マシンから取得できる

#### Scenario: 同じ状態で再実行する

- **WHEN** 前回の同期後にファイルが変更されていない
- **THEN** リモートと同期用リポジトリのコミットIDは変わらない
